# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> **Naturaleza de la fase:** fase 100% diagnóstica (UI-01/UI-02/UI-03). No se implementa código: el contrato cubre (a) el diseño de los **entregables** (informe de hallazgos + plan de reubicación) y (b) un **contrato de estado objetivo** (target-state) que da fundamento de diseño concreto a las propuestas del plan. La ejecución (UI-04/UI-05) es v2. El árbol `app/` queda sin diffs (criterio de éxito 4).

## Design System

| Property | Value |
|----------|-------|
| Tool | none — PySide6/Qt Widgets (shadcn/Tailwind no aplican: desktop, no web) |
| Preset | not applicable |
| Component library | Qt Widgets (QPushButton, QTableWidget, QTreeWidget, QListWidget, QComboBox, QCheckBox, QRadioButton, QGroupBox, QTabWidget, QCalendarWidget, QScrollArea) |
| Icon library | none — glifos unicode/emoji existentes (⟳ 🗑 📁 ⚙ + − × ✎ ⧉ 📷). No se introducen iconos nuevos |
| Font | Segoe UI / Helvetica Neue / Arial sans-serif (QSS `theme.py:88`); mono: Cascadia Mono/Consolas para URL del panel WiFi (`wifi_panel.py:116`) |

**Regla estética (PROJECT.md):** se mantienen tema oscuro/claro + acentos existentes. Este contrato **documenta la baseline congelada** (para que el informe no proponga rediseño) y declara el target-state **solo en ubicación/organización**, nunca en estética.

## Spacing Scale

**Baseline de la app (congelada, documentada no rediseñada):** paddings QSS 4/6/8/10/20px (`theme.py:105-115`), márgenes de diálogo 16h/14v (p. ej. `source_picker.py:39`), spacing 8-12.

**Contrato de espaciado (target-state, múltiplos de 4):**

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gaps de iconos, padding compacto |
| sm | 8px | Spacing estándar dentro de filas de diálogo y grupos |
| md | 12px | Spacing vertical entre secciones de diálogo |
| lg | 16px | Márgenes horizontales de diálogo (shell compartido) |
| xl | 24px | Separación entre grupos de la ventana principal |
| 2xl | 32px | Márgenes de la ventana principal / wizard |
| 3xl | 48px | Separación de zonas mayores |

**Shell de diálogo compartido (target-state):** margins `16px h / 12px v`, spacing `8px` — unifica los valores actuales dispares (14/16/24) en un único contrato (heurística de consistencia D-05).

Exceptions: botones de icono fijos a 28×28px en la header bar (`main_window.py:296`) — por debajo del objetivo 44px de touch pero **baseline congelada**; el informe la documenta, no la cambia. También `QDialog QPushButton { min-width: 70px }` (`theme.py:473`).

## Color

Valores del tema oscuro (el claro espeja: `bg #ffffff`, `bg_elevated #f6f8fa`, `accent #0969da`, `success #2f9e55`, `warning #9a6700`, `danger #cf222e` — `theme.py:41-63`).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0d1117` (bg) | Fondo de ventana, inputs, scrollbars |
| Secondary (30%) | `#161b22` (bg_elevated) | Paneles (`#HeaderBar`, `#SessionsPanel`), diálogos, listas, árboles, tarjetas, tabs |
| Accent (10%) | `#58a6ff` | Ver lista de reserva abajo |
| Destructive | `#f85149` (danger) | Solo acciones destructivas: `#DangerAction`, contador "0 errores", y las propuestas de borrado del target-state |

**Accent reservado EXCLUSIVAMENTE para** (`theme.py` + usos actuales):
- Bordes de focus (`QLineEdit:focus`, `QComboBox:focus`, hover de botones y checkboxes)
- Selección en tablas/listas/árboles (`accent_selection #1f6feb`)
- Identidad: app label `CosechaMedia` (`main_window.py:276`), `project_path_label` (`:315`), título del wizard, borde "hoy" del calendario (`selective_dump.py:202`)
- Tinte de fondo del tema (`tinted_bg`, ratio 0.15)

**Nunca** para acciones primarias de flujo — eso es `success` (`#3fb950`): `#PrimaryAction` (INICIAR INGESTA), chunk de progreso, checkbox checked. `warning` (`#d29922`) solo contador "0 pendientes".

**Contrato target-state:** toda propuesta del informe que introduzca énfasis debe usar `success` (acción de flujo) o `danger` (destructiva) — nunca ampliar la reserva de `accent`.

## Target-State Design Contract

> Contrato de estado objetivo: para cada control, ubicación actual → destino propuesto → justificación (heurísticas D-05: frecuencia, consistencia, contexto de acción, descubribilidad, distancia de ratón). Es un contrato de **diseño para el plan**, NO una orden de implementación (fase v2).

**Reglas transversales (D-03):** ninguna propuesta oculta, elimina ni colapsa un control; todo control del inventario queda accesible y descubrible en el estado objetivo. **Nombres de atributos de widgets están congelados** por los tests (`tests/test_e2e.py` usa `btn_start`, `table`, `source_list`) — el plan marca renombres como riesgo alto.

Cada ítem de `01-PLAN-REUBICACION.md` declara obligatoriamente:
1. **Control** (attr + label) y **ubicación actual** (archivo:línea).
2. **Destino propuesto** (zona, contenedor, orden en layout).
3. **Strings nuevos** (español fuente, listos para `tr()`).
4. **Riesgo**: tests (`test_e2e`, `test_source_picker`, `test_selective_dump`, `test_wifi_source`), i18n (nuevos strings), estética (QSS/tema).

6. **Score** (matriz abajo) y **orden de implementación**.

### Evidencia (D-04)

- **Inventario de widgets:** lectura estructurada de `main_window.py` y diálogos, por atributo público (los tests los nombran así).
- **Capturas offscreen:** mínimo **2 por zona** (estado inicial + estado configurado/poblado), 8 totales; PNG ≤ 1920px de ancho; nombres `captures/zonaA_estado-inicial.png`, `zonaA_configurado.png`, etc.; tabla de leyendas en el informe. Si la app no arranca offscreen, registrar la razón y usar captura manual si es posible (nunca omitir la columna sin motivo — regla no esconder nada aplica a la evidencia).

### Heurísticas (D-05 — definición operativa concreta)

| Heurística | Definición / medida |
|-----------|---------------------|
| Frecuencia de uso | Estimación por ciclo completo de operador (conectar → ingestar → formatear → reorganizar). 5 = cada ciclo; 3 = una vez por jornada; 1 = rara vez |
| Consistencia | Nº de violaciones del shell de diálogo compartido (hint + contenido + selección + `[stretch, Aceptar, Cancelar]`) y de la presentación de acciones destructivas |
| Contexto de acción | ¿El control está donde está la atención/tarea del operador en ese momento del flujo? Sí / Parcial / No |
| Descubribilidad | Pasos desde el estado inicial de la ventana: 0 = visible directo; 1 = dentro de un diálogo obvio; 2 = menú contextual/icono con tooltip; 3 = oculto o colapsado |
| Distancia de ratón | Ranking relativo de distancia desde el punto focal primario (`btn_start` / barra de progreso), normalizado 1-5 |

### Matriz de priorización (D-06 — pesos concretos)

- **Impacto** (1-5): 5 = frecuencia alta y bloqueo/fricción del flujo; 1 = pulido cosmético.
- **Esfuerzo** (1-5): 5 = toca múltiples diálogos + wiring (`main_window.py` + `source_picker.py` + `device_picker.py` como D-12); 1 = cambio local de layout.
- **Riesgo** (1-5): suma ponderada de tests (¿rompe `test_e2e`/pickers?), i18n (¿nuevos strings? ¿renombres?), estética (¿toca QSS/tema?).
- **Score = Impacto − (Esfuerzo + Riesgo)/2**. Bandas: **P1 ≥ 2.5**, **P2 1.0–2.4**, **P3 < 1.0**.
- **Orden de implementación:** dentro de cada banda, por flujo del operador (conectar → ingestar → formatear → reorganizar); D-12 (unificación de orígenes) precede a los ítems de su pestaña (dependencia).
