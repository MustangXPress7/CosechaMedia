<decisions>
## Implementation Decisions

### Fiabilidad de metadatos (FFprobe timeout)
- **D-01:** Ante timeout de ffprobe (10 s) se hace un **reintento** con timeout ampliado y
  `-read_intervals` de solo duración; si sigue fallando, la fila se marca como
  **"metadatos no verificados"** con aviso visible — nunca silencioso. Nada de "Unknown"
  mudo ni `file_size=0` sin señal. — **Reversibility:** reversible — el cambio vive en
  `metadata_engine.py` y en la presentación de la fila; deshacerlo no toca la DB ni contratos.
- **D-02:** La regla del usuario de la fase 1 ("no esconder nada en la interfaz", D-03 de
  `01-CONTEXT.md`) aplica: el estado "no verificados" debe ser evidente para el operador
  (tabla/informe/tooltip), no un valor mudo en la base de datos. — **Reversibility:** reversible.

### Garantía vs. doble hash MD5
- **D-03:** El hash MD5 se calcula **una sola vez** en un pase único (stream-through) durante
  la copia y se reutiliza: misma garantía de integridad, el destino no se vuelve a leer.
  Se conserva la semántica actual de borrado de destino corrupto en `copy_verified`.
  — **Reversibility:** costly — toca `copy_verified`/`copy_verified_with_progress` y
  `utils.calculate_md5`; revertir afecta a esos call sites y a la persistencia del hash en `files`.

### Watcher re-ingesta
- **D-04:** El inventario de archivos vistos se **persiste por fuente** (DB) y se poda por
  antigüedad en lugar de un cap duro de 10k; un archivo ya copiado no vuelve a copiarse ni a
  generar filas MD5 nuevas. — **Reversibility:** costly — requiere tabla/columna y migración
  en `db.py`; eliminar la persistencia toca esquema y watcher.

### Polling de dispositivos en la UI thread
- **D-05:** El chequeo periódico (`list_devices` WPD + `FtpBackend.is_reachable`) se mueve a un
  **worker/QThread que emite señales** (patrón `_StageWorker` existente en `main_window.py`);
  la UI no se congela. — **Reversibility:** reversible.

### Discreción del agente
- **DB path en desarrollo (bug de CWD):** el agente decide el fix por defecto sugerido en
  CONCERNS.md — anclar `_resolve_db_path` a la raíz del proyecto en dev
  (`Path(__file__).resolve().parents[2]`) y mantener el exe dir cuando `sys.frozen`.
- Detalle de dónde se muestra "metadatos no verificados" (columna en tabla de ingesta,
  informe CSV, tooltip) y umbrales de reintento/poda: a criterio del planner.
- Carrera "camera detection race" (edge case del token guard): aplicar el fix approach de
  CONCERNS.md (token único por detección en el call site). — **Reversibility:** reversible.

### Folded Todos
Ningún todo se plegó a la fase.

<code_context>
## Existing Code Insights

### Reusable Assets
- `_StageWorker` / `_TaskWorker` (`app/ui/main_window.py`) — patrón de worker QThread que
  ejecuta en background y emite señales; base para mover el polling de dispositivos
- `app/core/utils.py:calculate_md5` — función de hash ya factorizada; el pase único de D-03
  debe integrarse en `copy_verified` sin duplicar
- Singleton `db = DatabaseManager()` — patrón para la persistencia de inventario del watcher
- Test pattern `unittest` + `unittest.mock` + Qt offscreen (14 suites) — cada fix con su test
  de regresión (estilo F-01..F-05)

### Established Patterns
- Qt `Signal`s para actualización cross-thread de la UI (Ingestor, workers)
- `print(f"...")` para logging de errores — no añadir framework logging sin decisión
- SQLite por `db.get_connection()` con `check_same_thread=False` y WAL — respetar al
  persistir el inventario del watcher
- Módulos con singletons a nivel de módulo; los tests monkeypachean el atributo
  (`ingestor_module.db = ...`)

### Integration Points
- `metadata_engine.get_video_metadata` / `detect_camera_batch` — punto de reintento D-01
- `watcher._watch` (poda `scanned_files`) → nueva persistencia D-04
- `_resolve_db_path` en `app/core/db.py` — anclaje a raíz en dev (discreción)
- `Ingestor.copy_verified` + `_run_single_file` — pase único de hash D-03
- `main_window._auto_sync_check` 5 s QTimer → worker D-05

</code_context>
