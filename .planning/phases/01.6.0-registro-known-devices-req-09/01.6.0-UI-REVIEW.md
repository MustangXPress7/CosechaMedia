## Top 3 Priority Fixes

1. **`_populate_guardados()` destroys all list selections on "Examinar…" click** — If user selects an FTP profile or MTP device in Guardados and then clicks "Examinar…" to browse a folder, all four lists (folders, MTP, FTP, WiFi) are cleared and repopulated, destroying their selections. Fix: split `_populate_guardados()` into `_populate_guardados_folders()` so browse only refreshes the folders list, or preserve current selection state across the rebuild.

2. **No loading indicator during WPD device enumeration in Dispositivos tab** — When user opens the USB sub-tab, `ensure_loaded()` triggers WPD COM enumeration on a background thread with no visual feedback. If WPD takes 2-5 seconds (common), the user sees an empty pane with no indication of progress. Fix: add a `QLabel("Detectando dispositivos…")` or `QProgressBar` indeterminate spinner that is shown before `ensure_loaded()` and hidden when `selection_changed` fires.

3. **Inline font-size overrides create inconsistent typography** — The dialog overrides QLabel font-size to 12px in WiFi hint (line 243), placeholder tab (line 339), and Desconectados hint (line 471), but uses 11px for Desconectados delete hint (line 493). The QSS template already defines `QDialog QLabel { font-size: 12px }` (theme.py:520-521), making the 12px overrides redundant. Fix: remove the 12px inline overrides and rely on the QSS template's `QDialog QLabel` rule; only override where the QSS doesn't match (e.g., the 11px delete hint should be explicit about why it's smaller).

## Detailed Findings

### Pillar 1: Copywriting (3/4)

**Strengths:**
- Every user-facing string in `add_source_dialog.py` is wrapped in `self.tr()` — zero untranslated literals in the dialog itself. Spanish source language maintained throughout (add_source_dialog.py:64,84,89,94,104,106,129,139,142,152,154-157,170,173,217,229,239,252,256,291,299-301,328,335,467,475,489,497,556,564,567,625-629,649,660,667,678,689,721,737,752,765,893,909,911).
- Empty states are descriptive and consistent: "(sin carpetas guardadas)", "(sin dispositivos MTP guardados)", "(sin perfiles FTP guardados)", "(sin remitentes WiFi guardados)", "(sin remitentes WiFi)", "(sin dispositivos guardados)" — all parenthesized and Spanish.
- CTA labels are domain-appropriate: "Examinar…" (not generic "Browse"), "Crear nuevo…" (not "Add"), "Refrescar" (not "Refresh").
- Confirmation dialog for delete (line 624-633) is thorough: explains what happens, warns it can't be undone.

**Issues:**
- **WARNING:** `ftp_picker.py:21-41` `GUIDE_TEXT` is a large Spanish text block NOT wrapped in `tr()`. When language is switched to English, this guide stays in Spanish inside the embedded FTP sub-tab. Pre-existing issue (scope constraint: no pane refactor), but affects the dialog's visual coherence. *(Out of scope for this phase)*
- **WARNING:** "Usar esta configuración" button (line 129, 395-407) on the KnownDeviceCard overwrites the camera field, destination (if empty), and content mode without any confirmation. If the user had typed a custom camera name, it is silently replaced. The button label doesn't warn about this. Fix: add a tooltip or brief message before overwriting, or at minimum check if `camera_edit` already has non-empty text and show a confirmation.
- Minor: "Refrescar" button on Desconectados (line 475) duplicates the 5-second auto-refresh timer (line 187-190). The user has no way to know both exist or why the manual button is needed. Consider labeling it "Forzar actualización" or removing the redundancy.

### Pillar 2: Visuals (2/4)

**Strengths:**
- Clear hierarchical structure: QTabWidget (3 tabs) → nested QTabWidget (3 sub-tabs in Dispositivos) → embedded panes. The visual hierarchy via tab nesting is logical.
- KnownDeviceCard (QFrame) provides a distinct visual element when a known device is detected — differentiates from the rest of the form.
- PrimaryAction button styling on Aceptar provides visual weight differentiation from Cancelar.
- Disconnected device status uses color-coded text (success green / danger red) via `theme.color("success")` and `theme.color("danger")` (line 565-568).

**Issues:**
- **WARNING:** No iconography anywhere in the dialog. Tabs are text-only ("Guardados", "Dispositivos", "Desconectados"), sub-tabs are text-only ("USB", "FTP", "WiFi"), buttons are text-only. For an operator-oriented tool used on set, icons on the main tabs (folder icon, device icon, offline icon) would significantly improve scannability. The project already has SVG icons in `app/ui/assets/icons/`.
- **WARNING:** The ambiguity combo (`_ambiguity_combo`) is dynamically inserted into the camera row QHBoxLayout (line 837-841) and the `camera_edit` is hidden/shown (lines 852-853, 861, 864). This causes layout jumps — the camera row resizes when switching between `QLineEdit` and `QComboBox`. Fix: keep both widgets in the layout but hide/show without layout reinsertion, or use a `QStackedWidget` to swap them without size change.
- **WARNING:** The content row (line 161-163) `QComboBox` has no width constraint and can appear disproportionately wide compared to the camera/destination QLineEdit fields. Fix: add `self.content_combo.setMaximumWidth(150)` or similar to keep it proportional.
- Minor: No visual separator or grouping between the tab area (above) and the inline fields (below). The transition from tab content to "Cámara:", "Destino:", "Contenido:" fields is abrupt — a thin `QFrame` separator or a `QGroupBox` wrapper would help.
- Minor: The Guardados tab uses `QGroupBox` sections ("Carpetas guardadas", "Dispositivos MTP", etc.) which provide visual grouping, but the Dispositivos tab does not use the same pattern for its sub-tabs. The inconsistency between the two tabs' visual language is noticeable.

### Pillar 3: Color (3/4)

**Strengths:**
- Zero hardcoded hex colors in `add_source_dialog.py`. All colors obtained via `theme.color(...)` — fully theme-aware and dark/light mode compatible.
- Status colors correctly use semantic tokens: `theme.color("success")` for "Disponible" and `theme.color("danger")` for "Sin conexión" (line 565-568).
- KnownDeviceCard uses `theme.color('bg_elevated')` and `theme.color('border')` for its inline QSS (line 119-123), maintaining palette consistency.

**Issues:**
- **WARNING:** The KnownDeviceCard (line 115-136) uses an inline `setStyleSheet` with `QFrame#KnownDeviceCard { background-color: ...; border: ...; border-radius: 6px; padding: 8px; }`. This duplicates QSS template rules for QFrame (theme.py has no global `QFrame` rule, only `QGroupBox`). The inline approach is necessary but creates a visual island that doesn't participate in the global QSS cascade. If the theme template is ever updated to add QFrame rules, this inline style would override them. Fix: add a global `QFrame#KnownDeviceCard` rule to `_QSS_TEMPLATE` in theme.py instead.
- Minor: The 60/30/10 color distribution is ~90/10/0 in the dialog content area — bg (#0d1117) dominates, text (#f0f6fc) is secondary, and accent (#58a6ff) is only on the Aceptar button. For a form dialog this is acceptable, but the dialog feels visually flat compared to the main window which uses accent more liberally.

### Pillar 4: Typography (2/4)

**Font size distribution in add_source_dialog.py:**

| Widget | Source | Size |
|--------|--------|------|
| QLabel (dialog-level) | QSS template `QDialog QLabel` | 12px |
| WiFi hint | inline `setStyleSheet` (line 243) | 12px |
| Placeholder tab label | inline `setStyleSheet` (line 339) | 12px |
| Desconectados hint | inline `setStyleSheet` (line 471) | 12px |
| Desconectados delete hint | inline `setStyleSheet` (line 493) | 11px |
| QPushButton | QSS template | 11px |
| QGroupBox title | QSS template | 11px |
| QComboBox items | QSS template | 11px |
| QLineEdit | QSS template | 11px |

**Issues:**
- **WARNING:** The inline `font-size: 12px` overrides on lines 243, 339, and 471 are redundant with the QSS template's `QDialog QLabel { font-size: 12px }` rule (theme.py:520-521). Since these are all QLabels inside a QDialog, the QSS rule already applies. The overrides are no-ops in most cases but add maintenance noise. The exception is line 493 (`font-size: 11px`) which intentionally overrides the QSS — this should be documented why it's smaller.
- **WARNING:** Two font sizes (11px and 12px) are used for labels in the same dialog. The 12px is used for hints/descriptions, and 11px for field labels and the delete hint. While there is a logic (hints are larger), the visual effect is subtle inconsistency rather than intentional hierarchy. Consider whether hints should be 12px (current QSS default) or whether the delete hint should also be 12px.
- Minor: No font-weight variation is used in the dialog itself. The QSS provides `font-weight: 600` for QGroupBox titles and `font-weight: bold` for PrimaryAction buttons, but the dialog doesn't use weight for any custom hierarchy (e.g., making the "Dispositivo conocido" label bold).

### Pillar 5: Spacing (2/4)

**Spacing values used in add_source_dialog.py:**

| Location | Margins | Spacing |
|----------|---------|---------|
| Root layout (line 74-75) | (16, 14, 16, 14) | 12 |
| Dispositivos tab (line 202-203) | (0, 0, 0, 0) | 0 |
| USB sub-tab (line 211-212) | (6, 6, 6, 6) | 6 |
| FTP sub-tab (line 223-224) | (6, 6, 6, 6) | 6 |
| WiFi sub-tab (line 235-236) | (6, 6, 6, 6) | **8** |
| Desconectados tab (line 462-463) | (0, 0, 0, 0) | 8 |
| Placeholder tab (line 335) | (16, 16, 16, 16) | — |
| KnownDeviceCard (line 126) | (8, 6, 8, 6) | — |
| Guardados tab (line 645-646) | (0, 0, 0, 0) | 8 |

**Issues:**
- **WARNING:** WiFi sub-tab spacing is 8px while USB and FTP sub-tabs are 6px (lines 212, 224 vs 236). Since all three are peers in the same nested QTabWidget, they should share identical spacing. Fix: change WiFi sub-tab to `setSpacing(6)` for consistency.
- **WARNING:** Root layout vertical margins are 14px (line 74) while horizontal margins are 16px. This creates a subtle asymmetry — the dialog is slightly narrower at top/bottom than left/right. The QSS template doesn't define QDialog margins (the template uses implicit spacing). Standard Qt spacing is 9px or 11px, and this dialog uses 12px spacing + 14/16 margins, which is larger than typical. While not broken, it doesn't follow any consistent scale. Fix: standardize to (16, 16, 16, 16) or (12, 12, 12, 12) for consistency.
- Minor: The nested QTabWidget structure (DispositivosTabs inside SourceTabs) compounds padding: the outer tab pane has QSS `padding-top: 10px` (theme.py:488) and the inner tab adds its own padding. This double-padding may make the Dispositivos sub-tab content area feel cramped. The sub-tab containers use `setContentsMargins(6, 6, 6, 6)` (lines 211, 223, 235) which is tighter than the root's 16px margins, creating inconsistent density between the outer tab content and inner sub-tab content.

### Pillar 6: Experience Design (2/4)

**Strengths:**
- **Aceptar disabled state** is properly managed: `btn_aceptar.setEnabled(False)` initially (line 175), enabled only when source is selected AND camera is non-empty (line 878). This is correct and prevents premature submission.
- **Empty states** are honest and descriptive for all six lists/sections.
- **Delete confirmation** uses `QMessageBox.question` with Yes/No (line 624-633), explaining consequences and noting irreversibility.
- **Desconectados auto-refresh** via QTimer (line 186-193) provides live status without manual intervention.
- **Lazy loading** for USB/FTP sub-tabs (line 261, 267-279) avoids expensive WPD COM initialization until the user actually visits the tab.
- **Ambiguity handling** correctly shows a non-blocking combo for multiple candidates (line 360-361) rather than auto-selecting — adheres to ORIG-10/KNW-05.

**Issues:**
- **BLOCKER:** `_populate_guardados()` (line 699-767) clears and rebuilds ALL FOUR lists (folders, MTP, FTP, WiFi) whenever "Examinar…" is clicked (via `_browse_folder` → `_populate_guardados`). If the user has already selected an MTP device or FTP profile in Guardados, that selection is destroyed. The user must re-select after browsing. Fix: split `_populate_guardados()` into focused refresh methods (e.g., `_refresh_guardados_folders()`) so "Examinar…" only rebuilds the folders list, or snapshot/restore selection state across the rebuild.
- **WARNING:** No loading indicator when WPD COM enumerates devices on the USB sub-tab. `ensure_loaded()` (line 275) calls `mtp_pane.ensure_loaded()` which triggers `_DeviceScanWorker` on a background thread. During the 2-5 second WPD scan, the USB sub-tab shows an empty `MtpDevicePane` with no visual feedback. Fix: add a "Detectando dispositivos USB…" label or indeterminate `QProgressBar` in the USB sub-tab that is shown before `ensure_loaded()` and hidden when `selection_changed` fires.
- **WARNING:** No error feedback when device enumeration fails. `_load_desconectados()` (line 513-515) has a bare `except Exception` that silently sets `current_mtp = set()`. If WPD COM fails (e.g., COM not initialized, driver issue), the user sees an empty Desconectados list with no explanation. Fix: show a non-blocking error label like "No se pudo enumerar dispositivos MTP" on failure.
- **WARNING:** No keyboard shortcut to trigger Aceptar. In a QDialog, pressing Enter typically triggers the default button, but `btn_aceptar` is not set as the dialog's default button (`self.setDefaultButton` or via `QPushButton::setDefault(True)`). The user must click with the mouse. Fix: call `self.btn_aceptar.setDefault(True)` after creation, or add `self.btn_aceptar.setAutoDefault(True)`.
- **WARNING:** The "Usar esta configuración" button (line 128-134, handler at line 395-407) overwrites `camera_edit`, `dest_edit` (if empty), and `content_combo` without confirmation. If the user had manually typed a different camera name or selected a specific content mode, clicking this button silently replaces their choices. Fix: either (a) show a brief confirmation "¿Aplicar la configuración de [camera_model]?" or (b) only apply if the fields are empty, with a tooltip explaining the behavior.
- Minor: The Desconectados "Refrescar" button (line 475-477) duplicates the 5-second auto-refresh timer. Users may not understand why manual refresh exists alongside automatic refresh. Consider removing the button or adding a "Última actualización: hace X s" timestamp.
- Minor: No focus management in the dialog. When the dialog opens, focus goes to the first focusable widget (likely the Guardados QListWidget or the first tab). For faster workflow, initial focus should go to the most common starting point (Guardados folder list or the camera field).
- Minor: The `_browse_folder` QFileDialog title says "Seleccionar carpeta de la Tarjeta SD" (line 893), which assumes the user is always browsing for an SD card. If the user is browsing for a general folder (not an SD card), this title is misleading. Fix: use a more general title like "Seleccionar carpeta de origen".
