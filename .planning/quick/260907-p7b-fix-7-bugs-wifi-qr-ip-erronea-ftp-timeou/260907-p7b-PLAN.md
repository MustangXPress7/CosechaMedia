## T1 — Bug 1: WiFi QR anuncia IP errónea / `err_address_unreachable`

**Archivos:** `app/core/ftp.py`, `app/core/shoot_inbox.py`, `tests/test_ftp.py`, `tests/test_shoot_inbox.py`

**Contexto/raíz:** `local_ip()` (`ftp.py:93`) depende de `connect("8.8.8.8", 80)`; sin Internet devuelve `None` y `shoot_inbox.base_url()`/`_serve_page` cae a `"127.0.0.1"` → el móvil intenta su propio loopback → `err_address_unreachable`.

**Acción:**
- `ftp.py`: extraer `_default_route_ip()` (lógica actual). Añadir `local_ips() -> List[str]` (IPv4 no-loopback, determinista: `socket.getaddrinfo(socket.gethostname(), None, AF_INET)` + `_default_route_ip()` como respaldo). Reescribir `local_ip() = _default_route_ip() or (local_ips()[0] if local_ips() else None)`.
- `shoot_inbox.py`: `base_url()` y `_serve_page` usan `local_ip()`, mantienen `"127.0.0.1"` solo como último recurso (ya no se usa en el escenario habitual).
- `test_ftp.py`: mock de `socket.getaddrinfo`/`_default_route_ip` → `local_ips()` excluye loopback; `local_ip()` cae a la IP local cuando falla la ruta por defecto.
- `test_shoot_inbox.py`: `base_url()` no contiene `127.0.0.1` cuando `local_ip()` devuelve IP local.

**verify:** `python -m unittest tests.test_ftp tests.test_shoot_inbox`

**done:** T1 commiteado con `fix(core): ...`.

## T3 — Bug 3: botón «Detectar» explota la app (access violation COM)

**Archivos:** `app/core/mtp.py`, `tests/test_mtp.py`

**Contexto/raíz:** `_manager()` (`mtp.py:432-446`) cachea `PortableDeviceManager` en `_manager_local` y el caché sobrevive al `CoUninitialize` de `list_devices()` (`mtp.py:506-512`) o de `_WpdSession.close()` (`mtp.py:225-232`). La siguiente llamada en el mismo hilo reutiliza un objeto COM de un apartamento destruido → «Windows fatal exception: access violation» (no capturable con `try/except`).

**Acción:**
- Registrar siempre el estado COM del hilo en `_com_owner.initialized`:
  - `_WpdSession.__init__`: tras `CoInitialize()` → `_com_owner.initialized = True`.
  - `_WpdSession.close()`: si `self._com_initialized`, limpiar `_manager_local.device_manager = None` y `_com_owner.initialized = False` ANTES de `CoUninitialize`.
  - `WpdBackend.list_devices` finally (cuando `not was_initialized`): limpiar `_manager_local.device_manager = None` antes de `CoUninitialize`.
- `_manager()`: si no hay COM activo en el hilo (`_com_owner.initialized` falsy) **no** reutilizar caché; crear manager fresco.
- `tests/test_mtp.py`: mock de comtypes → 1) dos `list_devices()` seguidos en el mismo hilo: el `CreateObject` del manager se llama dos veces (no se reutiliza el stale); 2) dos sesiones secuenciales en el mismo hilo: ídem; 3) `_manager()` tras teardown crea uno nuevo.

**verify:** `python -m unittest tests.test_mtp` (el fallo preexistente `test_wpd_session_devicename_no_duplicate` es ajeno; el resto debe pasar)

**done:** T3 commiteado.
